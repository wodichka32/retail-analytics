# Olist — словарь данных

Источник: [Brazilian E-Commerce Public Dataset by Olist](https://www.kaggle.com/datasets/olistbr/brazilian-ecommerce) (Kaggle, версия 2).
Период: заказы с 2016-09-04 по 2018-10-17. Полная статистика: [olist_profile.md](olist_profile.md) (создаётся автоматически).
Связи между таблицами: [ER-диаграмма](../data_models/olist_source_er.md).

## Колонки

### orders

| Колонка | Тип | Описание | Примечания |
|---|---|---|---|
| order_id | строка (md5) | идентификатор заказа | первичный ключ |
| customer_id | строка (md5) | ссылка на customers | 1:1 с заказами |
| order_status | строка | delivered, shipped, canceled, unavailable, invoiced, processing, created, approved | 97% — delivered |
| order_purchase_timestamp | дата и время | момент покупки | без пропусков; основная бизнес-дата |
| order_approved_at | дата и время | подтверждение оплаты | 160 пропусков |
| order_delivered_carrier_date | дата и время | передача перевозчику | 1 783 пропуска; в 166 строках раньше покупки |
| order_delivered_customer_date | дата и время | доставка покупателю | 2 965 пропусков; в 23 строках раньше передачи перевозчику |
| order_estimated_delivery_date | дата | обещанная дата доставки | время всегда 00:00 |

## Проблемы качества данных

| № | Проблема | Чем грозит | Решение (Silver) |
|---|---|---|---|
| 1 | `customer_id` создаётся для каждого заказа; человек — это `customer_unique_id` | по `customer_id` повторных покупок ~0% | измерение покупателей по `customer_unique_id`; `customer_id` остаётся как связка |
| 2 | `review_id` не уникален (814 дубликатов) | соединение по `review_id` размножает строки | гранулярность — `(review_id, order_id)` |
| 3 | у 547 заказов несколько отзывов | соединение отзывов с заказами завышает выручку | перед соединением свести к одной строке на заказ (последний отзыв) |
| 4 | в геолокации ~53 точки на индекс, 26% полных дубликатов, 42 выброса | прямое соединение увеличивает число строк в ~53 раза | убрать выбросы, свести к 1 строке на индекс (медиана координат, самый частый город и штат) |
| 5 | 775 заказов без товаров (в основном `unavailable` / `canceled`) | пропадают из выручки по товарам | оставить в `fact_orders`, флаг `has_items` |
| 6 | у 461 отменённого заказа есть товары | завышают выручку без фильтра | правило выручки ниже |
| 7 | 610 товаров без категории; у `pc_gamer` и `portateis_cozinha_e_preparadores_de_alimentos` нет перевода | пустые категории в отчётах | заполнить `unknown`; добавить 2 перевода вручную |
| 8 | нарушен порядок дат (166: передача перевозчику раньше покупки; 23: доставка раньше передачи) | отрицательные длительности | флаг `is_timestamp_inconsistent`, исключать из логистических метрик |
| 9 | 8 доставленных заказов без даты доставки; 6 недоставленных — с датой | статус и даты противоречат друг другу | логистика считается по дате, строки помечены флагом |
| 10 | `shipping_limit_date` до 2020 года (12 строк — больше 60 дней после покупки) | выбросы в метриках сроков продавцов | флаг, исключать из этих метрик |
| 11 | 2016-09 … 2016-12 и 2018-09 … 2018-10 почти пустые (ноябрь 2016 = 0) | ложные падения и рост в трендах | окно анализа **2017-01-01 … 2018-08-31** |
| 12 | `sum(price + freight)` ≠ `sum(payment_value)` у 381 заказа (у 249 — больше чем на 1 BRL) | две разные «выручки» | выручка — по товарам; платежи — только для анализа оплат |
| 13 | у почтовых индексов есть ведущие нули | при чтении числом `01037` превращается в `1037`, соединения ломаются | всегда читать строкой |
| 14 | опечатка в названиях колонок `lenght` | косметика | переименовать в `length` |
| 15 | города продавцов — свободный текст: `sao paulo - sp`, `rio de janeiro / rio de janeiro`, e-mail, число | один город считается как несколько | `clean_city`; география в Gold — по почтовому индексу |
| 16 | часть названий городов записана в разложенном Unicode (`a` + комбинирующая тильда) | удаление диакритики по таблице символов их пропускает | удалять символы класса `\p{M}` |
| 17 | время записано как местное, без часового пояса | типы с часовым поясом сдвигают значения на пояс читателя | хранить как `TIMESTAMP_NTZ` |
| 18 | `product_category_name_translation.csv` начинается с UTF-8 BOM | читатели без Spark получают колонку `﻿product_category_name` | читать в кодировке `utf-8-sig` |

## Бизнес-правила

Правила зафиксированы до построения Gold, иначе метрики в разных витринах расходились бы.

| Правило | Решение |
|---|---|
| Покупатель | `customer_unique_id` |
| Дата заказа | `order_purchase_timestamp` |
| Валидный заказ для выручки | `order_status NOT IN ('canceled', 'unavailable')` |
| Выручка (GMV) | `sum(price)` по товарам валидных заказов; доставка считается отдельно (`freight_value`) |
| Средний чек (AOV) | выручка / число валидных заказов |
| Повторный покупатель | покупатель с ≥ 2 разными моментами покупки среди валидных заказов (несколько заказов в одну секунду — один чекаут) |
| Срок доставки | `order_delivered_customer_date − order_purchase_timestamp`, только доставленные заказы с непротиворечивыми датами |
| Опоздание | `date(order_delivered_customer_date) > order_estimated_delivery_date` |
| Окно для трендов | 2017-01-01 … 2018-08-31 |

# Слой Silver

Silver превращает строки из Bronze в типизированные, очищенные таблицы без дубликатов и отмечает проблемы
качества логическими флагами. Строки помечаются, а не удаляются: бизнес-правила применяются в Gold.

Запуск: `python -m src.transformations.olist.silver` (~70 с).
Код: [silver.py](../../src/transformations/olist/silver.py).
Отчёт о качестве: `data/silver/olist/_quality.json`. Если не проходит хотя бы одна жёсткая проверка, сборка падает.

## Приведение типов

| Строка источника | Тип в Silver | Функция |
|---|---|---|
| `yyyy-MM-dd HH:mm:ss` | `timestamp_ntz` | `to_ts` |
| `yyyy-MM-dd 00:00:00` (даты) | `date` | `to_date` |
| деньги | `decimal(12,2)` | `to_money` |
| количества, размеры | `int` | `to_int` |
| координаты | `double` | `to_double` |

Каждое приведение проверяется: если непустое значение источника превратилось в null, это ошибка разбора,
и сборка падает. В текущем запуске ошибок разбора 0.

Дата и время хранятся как `TIMESTAMP_NTZ` (без часового пояса). Olist записывает местное бразильское время
без смещения. Тип `timestamp` с часовым поясом сдвигал бы значения на пояс читателя (это поймал тест:
на компьютере с UTC+5 время 10:00 превращалось в 15:00).

## Очистка текста

`clean_text`: нижний регистр, удаление диакритики (готовые символы — через `translate`, разложенные —
через `\p{M}`), удаление мусорных символов `º £ ´ ³`, схлопывание пробелов, пустая строка → null.

`clean_city` (customers, sellers, geolocation) дополнительно оставляет только часть до `/`, `\`, `,` или ` - `
(`sao paulo - sp` → `sao paulo`) и заменяет на null e-mail и строки из одних цифр.
Города продавцов: 611 уникальных исходных значений → 586; 2 стали null.

Город остаётся свободным текстом. Для географии в Gold основой служит связь «почтовый индекс → геолокация»,
а не город, введённый вручную.

## Геолокация

1. Удаляются 42 точки за пределами прямоугольника Бразилии (широта −34…6, долгота −74…−34).
2. Для каждого индекса: медиана широты и долготы, самый частый город и штат (при равенстве — по алфавиту,
   чтобы результат был детерминированным), число точек и вариантов написания города.
3. По штату добавляется регион.

5 индексов состояли только из выбросов и исчезли (19 015 → 19 010).
Покрытие: у 99,72% строк покупателей и 99,77% строк продавцов индекс найден в геолокации;
остальные получают в Gold `geo_key = 'unknown'`.

## Жёсткие проверки (при ошибке сборка падает)

- 0 ошибок разбора;
- первичный ключ уникален и не пуст в каждой таблице;
- число строк не меняется во всех таблицах, кроме geolocation и category_translation;
- 0 «висячих» внешних ключей: orders → customers, order_items → orders / products / sellers,
  payments → orders, reviews → orders, products → category_translation.

Что изменилось между Bronze и Silver, показано в ноутбуке [03_silver](../../notebooks/olist/pipeline/03_silver.ipynb).

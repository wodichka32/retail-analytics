# Слой Bronze

Bronze хранит исходные данные без изменений, в формате Parquet, с техническими полями.
Это точка, с которой Silver можно пересобрать в любой момент: если преобразование оказалось ошибочным,
Silver строится заново из Bronze без повторной загрузки источника.

Запуск: `python -m src.ingestion.bronze_olist` (можно выбрать таблицы: `--tables orders reviews`).
Код: [bronze_olist.py](../../src/ingestion/bronze_olist.py), Spark-сессия: [spark.py](../../src/utils/spark.py).

## Структура

```
data/bronze/olist/
  _manifest.json
  customers/part-*.parquet
  orders/
  order_items/
  products/
  sellers/
  payments/
  reviews/
  geolocation/
  category_translation/
```

## Правила

| Правило | Причина |
|---|---|
| Все колонки источника хранятся как `string` (`inferSchema = false`) | Bronze хранит данные в том виде, в каком они пришли. Автоопределение типов теряет информацию (индекс `01037` → `1037`) и незаметно меняется вместе с данными. Типы задаются явно в Silver |
| Названия колонок не меняются, включая опечатки (`product_name_lenght`) | переименование — это преобразование, оно относится к Silver |
| `multiLine = true`, `escape = '"'` | в комментариях к отзывам есть переносы строк внутри кавычек: 99 224 записи занимают 104 719 строк файла |
| `mode = FAILFAST` | битая строка останавливает загрузку, а не превращается молча в пустые значения |
| Таблица перезаписывается целиком | источники — статичные выгрузки |
| Число строк сверяется с независимым разбором (модуль `csv` из Python) | ловит ошибки многострочных полей и кавычек; при расхождении сборка падает |

## Технические поля

| Колонка | Тип | Содержимое |
|---|---|---|
| `_source` | строка | `olist` |
| `_source_file` | строка | имя CSV-файла |
| `_ingestion_timestamp` | дата и время (UTC) | начало загрузки |
| `_batch_id` | строка | `yyyyMMddTHHmmssZ`, общий для всех таблиц одного запуска |

## Манифест

`_manifest.json` хранит id загрузки, время и для каждой таблицы: исходный файл, размер, список колонок,
число записей в CSV, число строк в Parquet и статус. Проверка полноты по манифесту показана в ноутбуке
[02_bronze](../../notebooks/olist/pipeline/02_bronze.ipynb).

## Наблюдения

- `product_category_name_translation.csv` начинается с UTF-8 BOM. Spark убирает его из заголовка;
  любой другой код, читающий файл, должен использовать кодировку `utf-8-sig`.
- Пустые поля CSV читаются как `null` (например, 160 пропусков в `order_approved_at`), а не как пустые строки.
- На Windows при запуске PySpark печатает `The system cannot find the path specified.`
  Это сообщение встроенных `.cmd`-скриптов, на работу оно не влияет.
